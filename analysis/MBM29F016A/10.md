This chip holds one byte lane of a 32-bit bus: every fourth byte of a ZIP archive. Data lines D0 and D2 are swapped on the chip. The first 0x075596 bytes are near-random compressed data. A lane-split ZIP central directory entry and end-of-central-directory record follow at 0x075596–0x0755AA, and the rest of the chip is erased. Once D0 and D2 are swapped back, those last 21 bytes read as every fourth byte (offsets 1, 5, 9 …) of a `PK 01 02` entry with a 12-byte file name, followed by a `PK 05 06` record. The fit holds only at a stride of 4. No local file header is visible, so the start of the archive is probably on another bank of chips.

## Layout

| Offset | Size | Contents |
|---|---|---|
| 0x000000 | 0x075596 | Compressed data, one lane of four (entropy 7.95–7.99 bits/byte per 64 KB sector). Probably the deflate stream of the archive's one member. |
| 0x075596 | 0x00000F | Lane-split ZIP central directory file header: one entry, 12-byte name, no extra field (`4B 00 00 A9 69 11 AC 00 00 00 00 00 30 53 4E` after the bit swap) |
| 0x0755A5 | 0x000005 | Lane-split end-of-central-directory record (`06 00 00 00 00`) |
| 0x0755AA | 0x000001 | `00` padding past the end of the record |
| 0x0755AB | 0x18AA55 | Erased (`FF`) to the end of the chip |

## Findings

- **Bit order: D0 and D2 swapped.** All eight bit positions are set about 52% of the time. Bits next to each other within a byte are weakly correlated, and that correlation forms a chain. The chain is b7–b6–b5–b4–b3–b0–b1–b2, not b7…b0: b3–b2 and b2–b0 show no correlation, while b3–b0 and b0–b1 do. Swapping D0 and D2 makes it a straight chain. The swap also turns the tail bytes into valid ZIP fields (raw `4E` becomes `4B` `K`, raw `03` becomes `06`). All decoded values below have the swap applied.
- **Stride 4.** The tail bytes from 0x075596, after the swap, are `4B 00 00 A9 69 11 AC 00 00 00 00 00 30 53 4E 06 00 00 00 00 00`. They match a central directory file header and its end record only when read as every fourth byte, at offsets 1, 5, 9 … 57 of the entry and then 3, 7, 11, 15, 19 of the end record:
  - entry +1 `K` (signature `PK 01 02`), +5 `00` (version made by, high byte = MS-DOS/FAT host), +9 `00` (flags high), +13 `A9` (DOS time high byte: hour 21, minutes 8–15), +17 `69` (CRC-32 byte 1), +21 `11` (compressed size byte 1), +25 `AC` (uncompressed size byte 1), +29 `00` (name length high), +33 `00` (comment length high), +37 `00` (internal attributes high), +41 `00` (external attributes byte 3), +45 `00` (local header offset byte 3);
  - name bytes 3, 7 and 11 are `0`, `S`, `N`. The end record starting 58 bytes after the entry fixes the name length at 12 with no extra field or comment. That fits an 8.3 name of the form `???0???S.??N`, probably `.BIN`;
  - end record +3 `06` (signature `PK 05 06`), +7 `00`, +11 `00` (entry count high), +15 `00` (directory size byte 3), +19 `00` (directory offset byte 3). One more `00` follows, past the 22-byte record, so the archive was zero-padded to a word boundary or further.
  - A stride of 2 does not fit: the byte after `K` would have to be `02` from the signature, but it is `00`.
- **One archive member.** The 6 lane bytes before the entry (`8E BB 7A 97 97 A8`, read backwards) are not ASCII, so no earlier central directory entry ends there. They look like the tail of the compressed stream. (A previous entry with a non-ASCII name or an extra field cannot be ruled out.)
- **No local header on this chip.** A local header with the same alignment would show `0`, `S`, `N` at stride 4. That pattern occurs only in the central directory. Byte 0 of the chip also does not fit any lane of `PK 03 04`. The compressed stream starts before this chip's address range, probably on a lower bank. The compressed-size byte (`11`) also does not fit an archive that starts at offset 0 of this bank.
- **The compressed data looks like deflate.** Sector entropy is 7.95–7.99 and there are no other signatures. Two stretches repeat with a 9-byte period on this lane, 36 bytes in the full stream. One is at 0x0582C7–0x05836F (`70 06 38 84 19 C0 0B E0 07` raw) and the other at 0x060D55–0x060E5D (`27 7F F1 40 0C 9F FD D0 02` raw). This is what deflate produces when it codes the same long match over and over, for example across fill or padding in the uncompressed file. The 0/1 bias rises from about 0.51 to 0.54 after 0x056000, which suggests the uncompressed content changes there.
- The data is not lane-split text or code: no magic, ASCII string or bit permutation gives readable content at stride 1. A brute-force search of all 40,320 bit permutations for ZIP, gzip, xz, LZMA, uImage and English found nothing beyond chance.

## Device

Unknown (low confidence). The image shows a board with at least four MBM29F016A chips on a 32-bit data bus, at least 8 MB per bank, and D0/D2 crossed between chip and bus. That kind of wiring swap is common on arcade and embedded boards. The board stored a firmware or data package as a ZIP file written by a DOS/Windows tool, with one member whose 8.3 name probably ends in `.BIN`. The package was large enough to run over from another bank into this one. A 5 V 16 Mbit part suggests late-1990s to mid-2000s hardware.

## Open questions

- **Full file name, CRC, sizes and date:** the other three lanes of this bank hold the remaining bytes of the central directory entry and end record. Interleave them with this chip at the same offsets, applying the D0/D2 swap to each chip that needs it.
- **Lane index:** this chip carries archive bytes at offsets congruent to (directory start + 1) mod 4. The absolute lane depends on the directory's alignment, which the other lanes or the end record's directory-offset field would give.
- **Start of the archive:** the local header and the start of the deflate stream should be on chips mapped below this bank. Once all lanes are joined, the member should inflate.
- **Compression method:** the method field sits at entry offsets 10–11, which are not on this lane. Deflate is assumed from the statistics only.

## Method

Python 3 (no third-party modules): per-sector entropy and erased-region map, byte and bit histograms, and a bit-pair covariance matrix within and across bytes, which gave the D0/D2 swap. A periodic-run search found the 9-byte repeats. A brute-force search over all 8-bit permutations for archive magics and English text, plus deflate, zlib and LZMA trial decompression at early offsets, found nothing. Binwalk found no signatures. The tail was decoded by hand against the ZIP central-directory and end-record layouts at strides 1, 2 and 4.
