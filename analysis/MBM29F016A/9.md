This chip is one byte lane of a 32-bit, big-endian flash bank. Four of these chips make 8 MB, and the bank holds a single file: a compressed ("-mz") Cisco IOS 12.2 router image, almost certainly for a Cisco 2600-series router (Motorola MPC860 PowerPC). The chip has the byte at every address ≡ 2 (mod 4), which is bits 15–8 of each 32-bit word, and its data lines D0 and D2 are swapped. Three pieces of evidence settle it. The lane bytes line up with PowerPC instruction fields: `mflr`/`mtlr` show as `02`/`03`, `mr` as `1B`, and the `bl` displacement bytes point at a function prologue. The deflate tables `cpdist` and `mask_bits` appear as exact lane slices. The text lines up with Cisco strings such as `Self decompressing the image : ` and `Cisco Internetwork Operating System Software` when every fourth character is taken.

## Layout

All offsets are on this chip. Lane offset *k* corresponds to address 4*k*+2 in the 8 MB bank. Byte values are after the D0/D2 swap is undone, unless marked raw.

| Offset | Size | Contents |
|---|---|---|
| 0x000000 | 16 B | Lane slice of a 64-byte Cisco flash file header: magic byte `0B`, filename characters `6 i z 2 a n` |
| 0x000010 | 21 B | Lane slice of the ELF header and program header of the IOS image (file offset 0x40) |
| 0x000025 | ~3.5 KB | PowerPC code of the self-decompressor (about 88 prologues, about 90 epilogues) |
| 0x000E00 | 51 B | Small data patterns |
| 0x000E33 | 552 B | Decompressor message strings (one character in four) |
| 0x00105B | 120 B | Inflate tables: zero lanes of `cplens`/`cplext`, `cpdist` at 0x0010A9, `mask_bits` at 0x0010C7 |
| 0x0010D3 | 104 B | Cisco `CW_` image-information block and IOS banner (one character in four) |
| 0x00113B | 5 B | Unexplained bytes `FA AC 11 77 F2` |
| 0x001140 | 10 B | Lane slice of the ZIP local file header (bank address 0x4500) |
| 0x00114A | ~1.6 MB | Deflate data of the ZIP member, entropy about 7.96 bits/byte |
| ~0x1A4000 | ~368 KB | Still compressed, statistically different: entropy about 7.98, 1-bit bias closer to 50 % |

No erased (`FF`) or zero-filled sectors. Every 64 KB sector holds data.

## Findings

- **Bit order D0↔D2.** I scored all 40,320 data-bit permutations against English letter frequencies over the text area at 0x000E33. Swapping D0 and D2 scored best by a wide margin. Two tables confirm it. Raw `00 04 06 03 09 18 30 60` at 0x0010B0 becomes `00 01 03 06 0C 18 30 60`. Raw `04 07 1F 7F` at 0x0010CB becomes `01 07 1F 7F`.
- **Stride 4, not 1 or 2.** Adjacent letters in the text are statistically independent. A letter-pair score is negative at stride 1 and 2 and about zero at stride 4. Known strings only match when every fourth character is taken, for example `leps  g ` at 0x000EC9 = `Self decompressing the image : `[2::4].
- **Lane position.** Several independent fields agree that this chip holds address ≡ 2 (mod 4), bits 15–8 of the big-endian word:
  - Flash-header magic byte `0B`.
  - ELF `e_ident` byte `L` at 0x000010.
  - ZIP signature byte `03` at 0x001140, which puts the header at a word-aligned 0x4500.
  - `bl` displacement bits 15–8 (below).
- **PowerPC (big-endian) code.**
  - The pattern `FF 02 00` (`stwu r1,-n(r1)`; `mflr r0`; `stw r0`) occurs 88 times in the code area, starting at 0x000057.
  - `00 03 00 00` (`lwz r0`; `mtlr r0`; `addi r1`; `blr`) occurs 90 times.
  - `1B 23 2B 33 3B 43 4B` at 0x000774 is the rB field of `mr rN,r3` … `mr rN,r9`, which saves the argument registers.
  - Neither pattern occurs anywhere in the compressed data.
- **Branch targets check out.**
  - At 0x000917–0x000D2C, repeated call sites `48 F8 03 00 00 xx 06 F8 1B` have an `xx` that falls from `F4` to `E4` as the caller address rises. That is bits 15–8 of a backward `bl` displacement.
  - All 13 of these calls resolve to the window 0x000634–0x00063E. A prologue starts at 0x000634 (bank address 0x18D0).
  - Wrapper stubs at 0x000384–0x000634 all call a common routine near bank address 0x1B8.
- **Cisco flash file header** at 0x000000 (bank 0x0000):
  - Magic byte `0B`, consistent with the Cisco flash file magic `BAD00B1E` (as I recall it).
  - Length bits 15–8 = `56`; flags byte `FF`.
  - Filename characters 2, 6, 10, 14, 18 and 22 are `6 i z 2 a n`, which fits `c2600-i?-mz.122-??a.bin`.
  - Characters 26 onwards are NUL.
  - I found no second file header in the chip.
- **ELF header** at bank 0x40:
  - `e_ident` = `.ELF`, version 1.
  - Entry and `p_vaddr` bits 15–8 are `80`, consistent with the usual 2600 load address 0x80008000.
  - `p_filesz` bits 15–8 = `55`; `p_memsz` bits 15–8 = `DD`.
- **Decompressor strings** (lane slices of known Cisco texts):
  - `Self decompressing the image : ` at 0x000EC9.
  - `Error : compressed image checksum is incorrect` at 0x000EA9.
  - `Expected a checksum of ` at 0x000EB8.
  - `Error : memory requirements exceed available memory` at 0x000E95.
  - `Uncompressed image checksum` at 0x000EEB.
- **Inflate tables.** The gzip/Info-ZIP `inflate.c` tables use 16-bit (`ush`) entries. Taking the high bytes of the odd entries reproduces the lane exactly:
  - `cpdist` (1, 2, 3, 4, 5, 7, … 24577) gives `00…00 01 03 06 0C 18 30 60` at 0x0010A9.
  - `mask_bits` gives `00 00 00 00 01 07 1F 7F` at 0x0010C7.
- **`CW_` image information** (lane slices):
  - `CW_BEGIN$` at bank 0x434D.
  - `CW_IMAGE$C26…` at 0x4361.
  - `CW_FAMILY$` with a 5-character value whose second character is `2` (fits `C2600`).
  - `CW_FEATURE$` with a 7-character value whose 4th character is `P`.
  - `CW_VERSION$12.2(??a)`.
  - `CW_MEDIA$RAM$` (all four lane characters match).
  - `CW_SYSDESCR$Cisco Internetwork Operating System Software …`.
- **IOS banner.** A length-constrained fit of the standard banner against the lane gives exactly one solution, with no mismatches: `IOS (tm) C?6?0 Software (` + 11-character image name + `), Version 12.2(2?a), RELEASE SOFTWARE (fc?)`, then `Technical Support: http://www.cisco.com/techsupport`, `Copyright (c) 1986-200? by cisco Systems, Inc.` and `Compiled … ??-A??-0? 0?:?? by k…`. The month starts with `A` (April or August).
- **ZIP local header** at 0x001140 (bank 0x4500). The lane holds header bytes 2, 6, 10, … 38:
  - Signature byte `03`; flags low byte `00` (not encrypted, no data descriptor).
  - Time low byte `69`; CRC-32 byte 0 `23`.
  - Compressed size byte 0 `30`; uncompressed size byte 0 `9C`.
  - Name length `0C` (12 characters); name characters 0, 4 and 8 are `C`, `0`, `.`.
  - Data starts at bank 0x452A (lane 0x00114A) if there is no extra field.
- **Compressed data.** The rest of the chip has a uniform bias toward 1-bits (53 % in every bit position) and has no structure. That is what one lane of deflate data looks like here. There is no ZIP central directory or end record on this lane, so the archive and the file probably run to or past the end of the bank.

## Device

**Cisco 2600-series modular router (MPC860 PowerQUICC), 8 MB flash SIMM built from four MBM29F016A chips.** Confidence: high for a Cisco IOS 12.2 image on a big-endian PowerPC 32-bit flash bank, medium-high for the 2600 platform. Five clues point to the 2600: the flash filename starts `c2600-`, the family field reads `C2?…`, the banner platform has a `0` in 4th place, the load address is 0x8000xxxx, and the CPU is PowerPC. The 1700 also uses an MPC860 but would read `1` where this lane reads `2`. The image is a mainline 12.2 rebuild, `12.2(2?a)`, built in 2003–2005 (from the copyright year). The feature set cannot be pinned down: the CW_IMAGE field fits a 2-letter feature code (`C2600-??-M`), but the banner fit needs an 11-character image name. Resolving that needs the other lanes.

## Open questions

- **Exact image name, feature set and build date.** Lanes 0, 1 and 3 of bank addresses 0x434C–0x44EA hold the other three characters of every four. Interleaving them would give the full `CW_` block and banner.
- **Contents of the ZIP member and its full name and sizes.** This needs all four lanes interleaved (stride 4, D0/D2 swap to undo here, and possibly on the partners). Then unzip the member at bank 0x4500.
- **Why the last ~368 KB differ statistically.** It could be a different part of the uncompressed image (data versus text), or the file ends and older data follows. File length bits 31–16 (on lanes 0/1 at bank 0x0004) would show where the file ends.
- **The 5 bytes at 0x00113B** just before the ZIP header (`FA AC 11 77 F2`). Possibly the end of the CW block, or a checksum or size word of the mzip wrapper. Check them against the partner lanes.

## Method

I used Python (`python3 -I`), `xxd`, `strings` and `binwalk` in a temporary directory. The steps were:

1. Per-sector entropy, fill and bit statistics.
2. A brute-force search over all data-bit permutations, scored on letter frequency. This found the D0/D2 swap.
3. Skip-gram letter statistics to choose stride 4.
4. Searches for lane-split structures (ZIP headers at each alignment, deflate and CRC tables, ELF fields).
5. PowerPC instruction-field patterns (`stwu`/`mflr`/`mtlr`/`mr`) and `bl` displacement arithmetic to confirm the architecture and lane.
6. Every 4-character phase of candidate Cisco strings, matched against the lane text. A length-constrained template fit then decoded the IOS banner.

I ran no code from the dump.
