This chip is byte lane 1 of the four-chip, 32-bit flash bank in a Seiko Instruments (SII) **NS-2482 Multi Access Server**, a Japanese ISDN, leased-line and frame-relay router from 1998. It pairs with dumps 3 (lane 0) and 4 (lane 2). The fourth chip is missing. This chip holds the strongest identifying strings of the set: the SNMP setup text `SysDescr "SII Multi Access Server NS-2482."` at 0x0FD9FE, `NS-OS version 3.1 start.` at 0x10F600 and `3rd Boot version 1.2 start.` at 0x162C71. Every 64 KB sector starts with the same `24 11` unit header as its siblings. The unit numbers of the untouched sectors equal 4 × sector + 1, which places this chip in lane 1. Sector 0 holds lane 1 of the striped boot area. The other sectors hold 512-byte blocks of a Unix-like flash file system. The main new result is that the `pocvup` file in unit 0x49 carries a complete, unstriped copy of the `POC-IDL Ver 3.0` loader. That copy supplies the bytes of the missing lane for that loader, and with them the loader disassembles cleanly as 68040 code driving an MC68360 QUICC.

## Findings

- **Lane 1 of the bank.** Units that were never rewritten (count 1 at +0x2C) carry 4 × sector + 1: 0x01, 0x05, 0x0D and 0x61 to 0x7D. Interleaving sector 0 of dumps 3, 5 and 4 (lanes 0, 1, 2, with a gap for lane 3) makes the boot area readable, for example `2n? Bo?t v?rsi?n 1?2 s?art?` and `POC?IDL?Ver?3.0?`.
- **The POC-IDL loader can be recovered in full.** The bank bytes from 0x4100 to 0xE1D8 (0xA0D8 bytes) appear linearly in this chip at 0x0F0BD8–0x0F1E00 and 0x0F2000–0x0FAEB0. All lane 0–2 bytes match, which fills in every missing lane-3 byte of the loader body. After the copy, at 0x0FAEB0, comes `0000A0D8 A6BE`: the length, then the low 16 bits of the byte sum (the computed sum is 0x2FA6BE). The 0x100-byte header at bank 0x4000 (`HPO?`, `0000A0??`, `0001A6??`, `000041??`) is not part of the copy. Its fields probably hold the same length and checksum (`0000A0D8`, `0001A6BE`).
- **POC-IDL is 68040 code for an MC68360 companion.** The recovered image is linked at CPU address 0x4000. It starts with `bra` over the version string, then `jsr $40E0`. Interrupt stubs pass `#$05000000` to C handlers. A routine at 0x4E8C writes `55` then `AA` to `$0500102F`, which is the MC68360 software watchdog service register (SWSR at REGB+0x102F). Another reads and modifies `$05001556`, the port C data register (PCDAT). This puts the QUICC register block at 0x05000000. The code uses `movec cacr/sfc/dfc`, `bfins` and `bfextu`. Its strings are a 68040 exception-vector table (`Defined for MC68020 and MC68030, no used by MC68040`), stack-frame dumpers and T1/E1 line-interface status text (`TAOS active`, `LOS has changed statu since last Clear LOS occurred`, `CCITT Recommendation G.703`, `FCC Part68,OptionA`, `0.6dB`…`3.0dB`).
- **`pocvup` is the flash updater for the boot area.** The root directory at 0x160200 lists `pocvup` as inode 0x1D5, next to `boot.3rd`, `bootconf`, `nsx.sys`, `init.root` and others. Its load module starts at 0x10F800 in unit 0x48 and continues in unit 0x49. The strings are `Pocvup version 1.0 start.`, `POC-vup Flash Rom Erase Error.` and `POC-vup Flash Rom Write Error.` (0x0F0B20). The POC-IDL image sits inside its `string` section, so this program rewrites the striped loader.
- **Executable format.** Every program in the file system starts at a block boundary with a 0x110-byte header that begins with magic `ABCD 0200`. The header holds the file size including the header at +0x2C (for `pocvup`, 0xB3F0) and the memory size at +0x30 and +0x34. Named section slots `code`, `const`, `string`, `data` and `ram` follow, each 0x1C bytes from +0x50. A table of offsets and sizes follows at +0xD4: for `pocvup`, code 0x0000/0xF54, const 0xF54/0x144, string 0x1098/0xA248, data 0xB2E0. Dump 5 has 48 of these headers (shown red in the block map).
- **File-system block numbering.** Two indirect blocks prove the mapping *FS block = unit × 127 + (block-in-unit − 1)*. The block at 0x0F1E00 (unit 0x49, block 15 = FS block 0x2445) lists `00002446, 00002447, …`, and the next data block is at 0x0F2000. The block at 0x12B400 (unit 0x47, FS block 0x2392) lists `00002393 …` and runs on into 0x23B8, the first block of unit 0x48. Block pointers are 32-bit big-endian, and each 64 KB unit gives 127 data blocks after its header block.
- **Directories.** Directory blocks use 32-byte entries: a 4-byte inode number and a 28-byte name. The root (0x160200) contains `admin(1) bin(2) boot.3rd(1B8) bootconf(4) driver(5) etc(6) init(7) init.root(1D2) mnt mnt2 mnt3 nsx.sys(1D3) pocvup(1D5) save(E)`. Part of `/driver` is at 0x164E00 (`MCardI.drv`, `QCH.drv`, `QMC.drv`, `e2prom.drv`, `en960.drv`, `fr.drv`, `l2hsd.drv` …).
- **Duplicate units.** Units 0x0E, 0x49 and 0x4E have byte-identical bodies on this chip and on dump 4, with different +0x26 values (8/5, 4/2, 3/13). Unit 0x48 here holds the same data as unit 0x48 on dump 3 (0x120000), shifted 0x400 bytes later. Both copies hold the `pocvup` header (dump 3 at 0x12F400, here at 0x10F800). So these are two layouts of the same files, probably from different file-system generations. Which copy is live is not recorded in the unit headers.
- **Spare unit.** Sector 14 (0x0E0000) is erased except for `24 11` at +0x00 and `00 07` at +0x26. It is the only such unit in lanes 0–2. It is probably the erase or transfer unit of the flash manager. If so, +0x26 is more likely an erase count than a generation number, but that is unconfirmed.
- **Second boot loader copies.** The startup code of the 2nd boot (bank 0x1010) also appears at the start of `pocvup`'s code (0x10F910) and in `boot.3rd` (0x160910). The full 2nd-boot image was not found linearly, so its lane-3 bytes stay missing.
- **No site data.** The only addresses are format strings and defaults. No configured IP addresses, host names or passwords were found.

## Device

**Seiko Instruments NS-2482 Multi Access Server**, system software Ver 3.1 (1998-08-31). Confidence: **high**. This chip contains `SII Multi Access Server NS-2482.` and `NS-OS version 3.1 start.`, and its unit headers fit lanes 0 and 2 (dumps 3 and 4) exactly. The hardware details are now also **high** confidence. A 68040-family CPU is shown by `movec cacr` and the 68040 exception text. An MC68360 QUICC with its register block at 0x05000000 is shown by the SWSR `55/AA` watchdog writes and the PCDAT access, both in the recovered POC-IDL code. A T1/E1 line interface is shown by the G.703, FCC Part 68 and line build-out strings.

## Open questions

- **Lane 3 is still missing** for the 2nd boot (bank 0x1000–0x3A0C), the boot-area headers and about a quarter of the file-system units. Next step: rebuild the 2nd boot from `boot.3rd` and `pocvup`, which share its startup code, or find the fourth chip.
- **Header fields.** The meanings of +0x26 (7 on the erased spare) and of the striped byte at chip offset 0x1FF (`78`/`FB`/`00` on lanes 0–2) are unknown. Next step: disassemble the flash driver in `nsx.sys` (strings `FlashEEPROM: No Memory.`, `[ERASE TO]` on dump 4).
- **Inodes.** The inode table, which would map inode numbers such as 0x1D5 to their first blocks, was not found in lanes 0–2. Next step: walk `pocvup`'s known block list (from 0x2433) backwards to search for a matching inode record.
- **Live copies.** It is not known which of the duplicated units (0x0E, 0x48, 0x49, 0x4E, 0x42, 0x54) is current. Next step: follow indirect-block chains from each copy and see which one they reach.

## Method

Python scripts printed the 48-byte header of every sector in dumps 3, 4 and 5 and classified each 512-byte block (zero, erased, text, code, directory, indirect, `ABCD` header). They also hashed blocks against all sibling dumps. Sector 0 of lanes 0–2 was byte-interleaved with a placeholder for lane 3. Regex searches with the lane-3 positions wildcarded found linear copies of the striped loader. Those copies were verified byte by byte and checked against the length and byte-sum trailer. The recovered POC-IDL image was disassembled with Capstone 5 in M68K/68040 mode at base 0x4000. Directory and indirect blocks were decoded by hand from hex dumps. The block map was rendered with Pillow.
